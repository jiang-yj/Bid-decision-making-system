# 投标决策辅助系统 · BDSS

纯前端单机版投标报价智能决策辅助系统。双击 `index.html` 即可在浏览器运行，无需安装、无需后端、无需构建工具，所有数据本地存储，不上传任何信息。

> ⚖ **合规声明**：本系统仅基于用户自行输入的假设进行敏感性分析，不提供、不建议任何与其他投标人协调报价的方案；模拟结果不构成对评标结果的承诺，实际以招标文件与评标委员会结论为准。

## 功能概览

### F0 合规提示条
- 首页顶部与报告页均展示合规声明，引用《招标投标法》及《实施条例》。
- **不可永久关闭**，仅本次浏览器会话可折叠，刷新/重启后再次显示，确保每次使用前的合规提醒。

### F1 配置面板（左侧）
九大配置区块，覆盖完整评标场景：

1. **项目信息** — 名称、编号、标段、最高限价 C_max、成本警戒线、币种
2. **基准价模型** — 5 种模型可选
   - 模型 A：算术平均法 `B = mean(Q₁..Qₙ)`
   - 模型 B：去极值平均法（去掉 1 个最高 + 1 个最低，≤2 家不退化）
   - 模型 C：下浮系数法 `B = mean(Q) × K`
   - 模型 D：复合基准价 `B = Σ(comp.value × w) / Σ(w)`，支持 avg / C_max / min / max / median
   - 自定义公式：Shunting-Yard 沙箱求值器，白名单函数与变量，禁用 `eval` / `new Function`
3. **得分规则** — 线性扣分（高于每 1% 扣 a，低于每 1% 扣 b）/ 分段扣分；舍入方式（四舍五入 / 向下 / 向上 / 不舍入）；得分下限
4. **废标规则** — 超限价无效 / 低于成本（无效 or 标记异常低价）/ 随机废标概率 p_reject / 最少有效家数
5. **伙伴投标人** — 固定值 / 窄分布（截断正态·均匀·三角）/ 样本驱动（历史报价拟合）；可标记"强制有效"（置信度低）
6. **随机对手** — 数量 + 分布列表（均匀 / 正态 / 三角 / 经验样本），参数 ≤1 视为限价百分比自动转绝对值；支持历史 CSV 导入
7. **我方策略** — 区间扫描（折扣下限~上限，步长）/ 指定列表
8. **模拟参数** — 蒙特卡洛迭代次数、随机种子、Worker 开关、进度回报间隔
9. **场景矩阵** — ①无伙伴纯随机 ②含伙伴（基准）③伙伴集体偏移 ④指定伙伴废标

### F2 结果面板（右侧）

- **F2-1 单点测算**：给定一组确定报价，输出基准价、各家得分、我方排名、有效家数、低置信标记。
- **F2-2 批量扫描（蒙特卡洛）**：对每个候选价跑 N 次模拟，输出：
  - 中标概率曲线 + 期望得分副轴折线图
  - 得分分布（P10/P50/P90 柱状图）
  - 排名分布（堆叠柱，共 100%）
  - 明细统计表（中标概率、期望得分/排名、最差排名、分位数、标准差、有效轮数）
- **F2-3 场景对比**：多场景中标概率曲线对比 + 各场景最优候选价表。

### F3 智能分析结论
- **三档建议价**：保守档（期望排名最优）/ 中性档（中标概率最高）/ 激进档（报价最低且胜率仍可接受）
- **可接受区间**：满足中标概率阈值的所有候选价范围
- **稳健性分析**：相邻报价档位胜率漂移幅度 + 最差假设下仍可接受的报价带
- **风险提示**：有效投标人不足 / 异常低价 / 对手集体压价 / 伙伴偏离
- **伙伴表回显**：所有伙伴假设的设定方式、报价/分布、强制有效标记、置信度

### F4 方案管理
- 方案列表（置顶优先，按更新时间倒序）
- 新建 / 载入 / 复制 / 改名 / 删除 / 置顶
- JSON 导入导出
- 内置示例方案一键载入
- 结果缓存（含批量结果与结论，下次打开直接回显）

### 导出与打印
- **CSV**：批量扫描明细 + 智能结论 + 合规声明（UTF-8 BOM，Excel 友好）
- **PNG**：所有图表导出（2x 像素比）
- **Markdown**：完整分析报告（含方案信息、批量结果、结论、风险、场景对比、伙伴回显、合规声明）
- **打印**：原生打印样式，隐藏配置面板与工具栏，自动展开结果块

## 快速开始

### 运行

```bash
# 方式1：双击 index.html（推荐）
# 方式2：命令行打开
open index.html          # macOS
xdg-open index.html      # Linux
start index.html         # Windows
```

> **首次运行需联网**：Alpine.js 与 ECharts 通过 CDN 加载（`defer`）。离线时 ECharts 不可用，图表会自动降级为表格展示，核心功能不受影响。

### 首次使用流程

1. 打开 `index.html`，系统自动载入内置示例方案（若本地无方案）。
2. 顶部下拉切换方案，或点击「方案管理」查看全部。
3. 在左侧配置面板调整参数（项目信息、模型、得分规则、伙伴、对手、策略）。
4. 点击右侧「单点测算」做快速验证。
5. 点击「批量扫描」运行蒙特卡洛模拟（5000 次 × 候选价数）。
6. 查看右侧图表与智能分析结论。
7. 点击「导出 Markdown」或「打印报告」生成成果文件。
8. 点击「保存」持久化方案与结果到 localStorage。

### 自检

点击顶部「自检」按钮，运行 5 个内置数值断言用例：

| 用例 | 场景 | 断言 |
|------|------|------|
| A | 算术平均法 3 家固定报价 | 基准价、我方得分、对手得分、排名手算对照（误差 ≤0.01） |
| B | 去极值平均法 4 家 | 去极值后基准价、得分 |
| C | 伙伴固定 95% ×2 + 对手 3 家 | 含伙伴基准价与得分 |
| D | 有伙伴 vs 无伙伴对照 | 伙伴报价高于对手均值时胜率方向正确 |
| E | 固定种子两次运行 | 期望得分、中标概率逐位一致（可复现性） |

## 核心公式示意

### 基准价 B

```
模型A（算术平均）：   B = (Q₁ + Q₂ + ... + Qₙ) / n
模型B（去极值平均）： B = mean( Q 去掉 1 个最高 + 1 个最低 )   （n ≤ 2 时全量平均）
模型C（下浮系数）：   B = mean(Q) × K
模型D（复合基准）：   B = ( Σ comp.value × comp.w ) / ( Σ comp.w )
                      comp.src ∈ {avg, C_max, min, max, median}
模型D（自定义）：     白名单沙箱求值，可用变量 Q/n/C_max/mean/min/max/median/K
                      可用函数 abs/min/max/round/floor/ceil/sqrt/log/exp/pow
```

### 得分 S

```
偏离率 d = (qi - B) / B           （有符号，正为高于基准，负为低于）
absDev% = |d| × 100

线性模式：   S = S_max - (d≥0 ? a : b) × absDev%
分段模式：   找到 d 所在区间 [seg.lo, seg.hi]
             S = S_max - min(seg.cap, seg.per × absDev%)
最终：       S = max(floorScore, S)，按 rounding/roundDecimals 舍入
```

### 排名
得分最高者第 1 名；**同分时报价低者优先**（防止恶意高价同分）。

### 中标概率
对每个候选价跑 N 次蒙特卡洛，统计我方得分为第 1 名的轮数占比：
```
winProb = (我方排第1的轮数) / 有效轮数 × 100%
```

### 废标规则
- 报价 > C_max（若 overCmaxInvalid）→ 无效
- 报价 < 成本警戒线 → 按配置（无效 / 标记异常低价但仍有效）
- 随机废标：每轮每家以 p_reject 概率被废（模拟不可控因素）
- 有效家数 < minValidBidders 时该轮丢弃（低置信）

```
投标决策系统/
├── index.html                主入口，布局骨架 + Alpine 模板 + 合规条
├── styles.css                全部样式（Flex/Grid、响应式、打印）
├── data/
│   ├── defaults.js           全局默认常量、币种、分布预设、合规文案
│   └── examples.js           3 个内置示例方案 + 历史 CSV 样本
├── js/
│   ├── config.js             Scheme schema、校验、迁移、候选价生成
│   ├── rng.js                伪随机数 + 分布采样（mulberry32 可控种子）
│   ├── model.js              基准价 5 模型、得分、废标、公式沙箱
│   ├── simulator.js          单点 / 批量 / 场景执行（纯函数，可注入 Worker）
│   ├── analyzer.js           聚合统计、三档建议、稳健性、风险、伙伴回显
│   ├── worker-manager.js     Blob Worker 构建、池化、中止、主线程降级
│   ├── storage.js            localStorage CRUD、导入导出、示例载入
│   ├── ui.js                 ECharts 封装（含表格降级）、渲染、导出、打印
│   ├── selftest.js           用例 A~E 数值断言
│   └── app.js                Alpine 组件、事件总线、演算接线
└── README.md                 本文档
```

### 架构分层

| 层级 | 模块 | Worker 安全 | 说明 |
|------|------|-------------|------|
| data | defaults / examples | ✓ | 纯数据 |
| config | config | ✓ | 纯函数，schema 与迁移 |
| rng | rng | ✓ | 纯函数，伪随机与分布 |
| model | model | ✓ | 纯函数，基准价与得分 |
| simulator | simulator | ✓ | 纯函数，蒙特卡洛 |
| analyzer | analyzer | ✓ | 纯函数，统计与文案 |
| worker-manager | worker-manager | ✗ | 操作 Worker API |
| storage | storage | ✗ | 操作 localStorage |
| ui | ui | ✗ | 操作 DOM / ECharts |
| selftest | selftest | ✗ | 调用模拟器 |
| app | app | ✗ | 顶层接线 |

> **Worker 安全**层的函数均为纯函数，通过 `.toString()` 注入 Blob Worker 执行，实现并行加速且保证 `file://` 协议下可靠运行。

### 脚本加载顺序

`index.html` 中所有脚本以 `defer` 按序加载，确保 Alpine 启动前 `BDSS.*` 命名空间与 `bdssApp()` 组件函数已就绪：

```
ECharts(CDN) → Alpine(CDN) → defaults → examples → config → rng → model
→ simulator → analyzer → storage → worker-manager → ui → selftest → app
```

## 使用指南

### 伙伴配置

| 方式 | 适用场景 | 参数 | 置信度 |
|------|----------|------|--------|
| 固定值 | 已确知伙伴报价 | 报价绝对值 | 高 |
| 窄分布 | 伙伴报价有小幅波动 | 中心(%)、偏差(%)、分布类型 | 中 |
| 样本驱动 | 有历史报价数据 | 逗号分隔的绝对值报价列表 | 中 |
| 强制有效 | 标记伙伴不参与废标判定 | 勾选框 | 低 |

> ⚠ 标记"强制有效"的伙伴假设置信度低，模拟结果需谨慎参考。

### 对手分布

参数值 ≤1 时视为限价百分比（自动转绝对值），>1 时视为绝对值。示例：
- `min=0.92,max=0.98` → 限价的 92%~98%
- `mean=0.95,std=0.02` → 正态分布 N(0.95, 0.02)

支持多分布列表，按顺序循环分配给每个对手（可模拟 A/B 两组不同水平对手）。

### 场景矩阵

| 场景 | 说明 |
|------|------|
| ①无伙伴纯随机 | 禁用所有伙伴，评估纯随机环境 |
| ②含伙伴（基准） | 当前伙伴配置作为基准假设 |
| ③伙伴集体偏移 | 所有伙伴报价整体上下平移 N% |
| ④指定伙伴废标 | 某个伙伴失效，评估依赖风险 |

### 随机种子与可复现性

- 固定种子下，相同参数两次运行结果**逐位一致**（自检用例 E 验证）。
- 不同候选价使用 `deriveSeed(baseSeed, index)` 派生子种子，保证各候选价独立但整体可复现。
- 修改种子即可得到不同随机序列，用于交叉验证。

## 合规说明

### 法律依据

- **《中华人民共和国招标投标法》**
  - 第三十二条：投标人不得相互串通投标报价，不得排挤其他投标人的公平竞争。
  - 第五十三条：投标人相互串通投标或者与招标人串通投标的，中标无效。
- **《中华人民共和国招标投标法实施条例》**
  - 第三十九条至第四十一条：禁止投标人之间串通投标等行为。

### 系统边界

本系统**仅**基于用户自行输入的假设进行敏感性分析：

- ✅ 提供：候选报价的期望得分、中标概率、排名分布统计
- ✅ 提供：方案参数敏感度分析、稳健性评估、风险提示
- ✅ 提供：伙伴假设的回显与置信度标记
- ❌ 不提供：任何与其他投标人协调报价的方案
- ❌ 不承诺：模拟结果不构成对评标结果的承诺

实际投标请以招标文件与评标委员会结论为准。

### 合规提示条机制

- 首页顶部：醒目橙色横幅，每次启动显示
- 报告页底部：打印/导出报告时附合规声明与法律依据
- **不可永久关闭**：仅本次会话可折叠，刷新或重启后再次显示

## 已知限制

1. **CDN 依赖**：首次运行需联网加载 Alpine.js 与 ECharts；离线时图表降级为表格（核心计算不受影响）。
2. **localStorage 容量**：单域名约 5~10MB；方案过多或结果过大可能触及上限，建议定期导出 JSON 归档。
3. **候选价上限**：单次批量扫描候选价 ≤50（防止误操作过大区间），建议步长 ≥0.5%。
4. **迭代次数**：默认 5000，可调至 1000~50000；过大将延长计算时间（Worker 加速下 10000 次约 2~3 秒）。
5. **浏览器兼容**：需支持 ES5+、Blob、Worker、TypedArray；推荐 Chrome 80+ / Edge 80+ / Firefox 75+ / Safari 14+。
6. **自定义公式**：沙箱仅支持白名单函数与变量，不支持赋值、循环、自定义函数定义。
7. **敏感度分析**：当前 `sensitivityTornado` 返回因素框架，完整 ±δ 双向模拟需 UI 触发（详见扩展清单）。
8. **多标段**：单方案仅支持单标段；多标段需建多个方案或扩展为子标段结构。
9. **打印**：依赖浏览器原生打印，复杂图表在打印分页处可能截断。

## 技术栈

- **渲染**：原生 HTML + CSS + Alpine.js 3（声明式响应）
- **图表**：ECharts 5（含表格降级）
- **计算**：纯 JavaScript（ES5 兼容），mulberry32 可控随机数
- **并行**：Blob Worker（纯函数 `.toString()` 注入，主线程降级）
- **存储**：localStorage（含内存降级）
- **依赖**：零构建工具、零 npm、零后端
