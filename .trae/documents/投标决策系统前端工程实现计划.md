# 投标报价智能决策辅助系统 — 前端工程实现计划

## Context

基于《投标决策系统需求说明书v1》交付一个**纯前端单机版**投标报价智能决策辅助系统。核心痛点：商务标报价编制依赖 Excel 手工穷举，工作量大、易出错、难复用。目标：用户配置报价模型/限价/加减分/伙伴/对手参数后，系统自动模拟多场景博弈，输出科学合理的建议报价区间。

**硬约束**：双击 `index.html` 即可运行，无需 npm/构建/后端；数据全本地（localStorage + 文件导入导出）；合规红线（仅基于用户自行输入的假设做敏感性分析，不提供协同报价方案）。

---

## 一、整体架构

### 技术选型
- **脚本加载**：多 `<script>` 经典标签按依赖顺序加载，挂载到全局命名空间 `BDSS`（非 ES Module，规避 file:// CORS 限制）
- **Worker**：计算核心写为纯函数（零 DOM/全局依赖），通过 `.toString()` 注入 **内联 Blob Worker**，file:// 下可靠运行
- **响应式**：Alpine.js v3（CDN UMD 构建），表单绑定 + 动态列表（伙伴/对手/场景）
- **图表**：ECharts（CDN），加载失败降级为表格
- **离线兜底**：vendor/ 目录可放本地 echarts.min.js + alpine.min.js（首次加载后无网络可用）
- **统计/PRNG**：自实现 mulberry32、Box-Muller 正态、三角分布、截断处理；支持固定种子复现

### 模块分层（每层一个 js 文件）

| 层 | 文件 | 职责 | Worker安全 |
|---|---|---|---|
| config | `js/config.js` | Schema、默认值、校验、版本迁移 | ✓ |
| rng | `js/rng.js` | PRNG + 分布采样 | ✓ |
| model | `js/model.js` | 基准价模型、得分计算、废标规则 | ✓ |
| simulator | `js/simulator.js` | 单点测算、批量蒙特卡洛、场景执行 | ✓ |
| analyzer | `js/analyzer.js` | 聚合统计、P10/P50/P90、敏感度、智能文案 | ✓ |
| storage | `js/storage.js` | localStorage 方案管理、导入导出、示例 | ✗ |
| worker-mgr | `js/worker-manager.js` | Blob Worker 构建、池化、中止信号 | ✗ |
| ui | `js/ui.js` | 渲染、ECharts 封装、表格降级、导出 | ✗ |
| app | `js/app.js` | 引导、中央状态、事件总线、接线 | ✗ |

依赖链：`rng ← model ← simulator ← analyzer ← app`；`config ← (all)`；前四层（rng/model/simulator/analyzer）为纯函数、零 DOM 访问，可被 `.toString()` 注入 Worker。

## 三、核心数据结构（Scheme Schema）

```js
BDSS.scheme = {
  meta: { id, name, createdAt, updatedAt, pinned, version: 1 },

  project: {                       // F1.1 项目信息
    name, code, section,
    C_max,                         // 最高限价（绝对值）
    costWarningLine,               // 成本警戒线（绝对值）
    currency: 'CNY'
  },

  pricingModel: {                 // F1.2 报价模型
    type: 'A'|'B'|'C'|'D'|'custom',
    params: {
      // A: {}                    算术平均
      // B: { trimLow:1, trimHigh:1 }  去极值
      // C: { K: 0.98 }           下浮系数
      // D: { components:[{src:'avg'|'C_max'|'min'|'max'|'median', w}] }  复合
      // custom: { formula:'mean(Q)*(1-0.02)', vars:['Q','n','C_max','mean','min','max','median','K'] }
    }
  },

  scoring: {                       // F1.3 得分规则
    S_max: 60,
    mode: 'linear'|'segmented',
    a: 1, b: 1,                    // 高于/低于基准每 1% 扣分
    segments: [{ lo:-1, hi:0, per:1, cap:100 }],  // 分段扣分
    rounding: 'round'|'floor'|'ceil'|'none',
    roundDecimals: 2,
    floorScore: 0
  },

  invalidRules: {                  // F1.4 废标规则
    overCmaxInvalid: true,
    belowCost: 'invalid'|'flag',
    p_reject: 0,                   // 单家随机废标概率 0~20%
    minValidBidders: 3             // 有效不足 N 家 → 标注置信度低
  },

  partners: [                      // F1.5 伙伴配置
    { id, name, enabled: true,
      method: 'fixed'|'narrow'|'sample',
      fixedQuote: 0,
      narrow: { center:0, spread:0, dist:'normal'|'uniform'|'triangular' },
      samples: [],
      forceValid: false }           // 视为必然有效 → 标黄
  ],

  opponents: {                     // F1.6 随机对手
    count: 5,
    distributions: [
      { id, type:'uniform'|'normal'|'triangular'|'empirical',
        params: { min,max } | { mean,std } | { a,b,c } | { samples:[] },
        group: 'A' }
    ],
    csv: ''
  },

  strategy: {                      // F1.7 我方策略空间
    candidateMode: 'range'|'list',
    range: { discountMin:0, discountMax:10, step:0.5, relativeTo:'C_max' },
    list: [0.92, 0.93]
  },

  simulation: { iterations:10000, seed:12345, useWorker:true, progressEvery:500 },

  scenarios: [                     // F1.9 场景矩阵
    { id, name, type:'noPartner'|'withPartner'|'partnerShift'|'rejectPartner',
      params: { partnerId, shiftPct }, enabled: true }
  ],

  results: { single:{}, batch:[], scenarios:[], updatedAt:ISO }  // F4 缓存
}
```

## 四、核心公式伪代码

### 基准价模型（操作绝对值有效报价 Q[]）

```
model_A(Q):     return mean(Q)
model_B(Q,p):   sort Q asc; 去掉 trimLow 个最低 + trimHigh 个最高;
                count≤2 时不退化,全量平均; 否则 mean(remaining)
model_C(Q,p):   return mean(Q) * K
model_D(Q,p):   val = Σ comp.value(Q) * comp.w;  return val / Σ comp.w  (权重归一)
model_custom:   sandbox.eval(formula, {Q, n, C_max, mean, min, max, median, K})
                // 手写 shunting-yard 递归下降求值器，白名单函数+标识符，禁用 eval/Function
```

### 得分计算（投标人 i，报价 qi，基准价 B）

```
d = (qi - B) / B                            // 有符号偏离率
if mode == 'linear':
    off = (d>=0 ? a : b) * (|d| * 100)       // 每 1% 扣 a/b 分
else 'segmented':
    seg = findSegment(segments, d)
    off = min(seg.cap, seg.per * (|d|*100))
score = max(floorScore, S_max - off)
score = round(score, rounding, roundDecimals)
winner = argmax(score); 同分 → 报价低者优先
```

### 废标规则（采样报价 qi 时）

```
if overCmaxInvalid and qi > C_max:       → invalid
if belowCost=='invalid' and qi < costLine: → invalid
if belowCost=='flag'    and qi < costLine: → flagged (仍有效)
u ~ U(0,1);  if u < p_reject:             → invalid
if count(valid) < minValidBidders:        → 丢弃本轮重采样
```

### 蒙特卡洛批量扫描

```
for each candidatePrice c in candidates:
    seed_c = hash(seed, index(c))           // 固定种子保证复现
    rng = mulberry32(seed_c)
    scores[] = [], ranks[] = []
    for i in 1..iterations:
        bids = [c] + samplePartners(rng) + sampleOpponents(rng)
        validBids = applyInvalid(bids, rules, rng)
        if |validBids| < minValidBidders: continue   // 跳过本轮
        B = basePrice(validBids, model, project)
        scored = [(qi, score(qi, B, scoring)) for qi in validBids]
        ranks.push(rankOf(c, scored))
        scores.push(score(c, B, scoring))
    // 聚合 → 期望得分、期望排名、中标概率(第1名占比)、P10/P50/P90、排名分布
```

### Worker 通信协议

```
Main → Worker:  { type:'run', jobId, scheme, candidates, iterations, seed, progressEvery, mode }
                { type:'abort', jobId }
Worker → Main:  { type:'progress', jobId, done, total, elapsedMs, etaMs }
                { type:'done', jobId, perCandidateStats:[] }
                { type:'aborted', jobId }
                { type:'error', jobId, message }
```

Worker 构建：`buildWorkerSource()` 拼接 `rng.toString() + model.toString() + simulator.toString() + workerMain.toString()`，通过 `Blob URL` 创建。池化：`min(hardwareConcurrency, 4)` 个 Worker，按 candidate 分片，每个 candidate 用 `hash(seed, index)` 独立种子保证跨 Worker 确定性。主线程降级：无 Worker 时 `setTimeout` 分块跑。

## 五、实现步骤

### 阶段 1：基础骨架与核心计算（config/rng/model）
1. `data/defaults.js` — 默认常量、币种、分布预设

4. `js/model.js` — 5 种基准价模型、score()、applyInvalid()、自定义公式沙箱（shunting-yard）

### 阶段 2：模拟器与分析器（simulator/analyzer）
5. `js/simulator.js` — singlePoint()、runBatch()、runScenario()
6. `js/analyzer.js` — aggregate()（期望得分/排名/中标概率/P10/P50/P90/排名分布）、sensitivityTornado()、autoConclusions()（保守/中性/激进三档建议、稳健性三问、风险提示）

### 阶段 3：Worker 与存储
7. `js/worker-manager.js` — buildWorkerSource()、createWorker()、消息协议、池化、中止、主线程降级
8. `js/storage.js` — localStorage CRUD、importJSON/exportJSON、loadExamples()

### 阶段 4：UI 与接线
9. `index.html` — 布局骨架、`<template>` 模板、合规提示条、脚本加载
10. `styles.css` — 全部样式（Flex/Grid、响应式、打印）
11. `js/ui.js` — renderChart()（ECharts 封装+表格降级）、表单渲染、导出（CSV/PNG/Markdown/打印）、合规回显
12. `js/app.js` — BDSS.state（Alpine reactive）、BDSS.bus 事件总线、接线、Alpine 组件

### 阶段 5：示例、自检、文档
13. `data/examples.js` + `samples/` — 2~3 个示例方案（至少一个含伙伴）+ 历史 CSV
14. `js/selftest.js` — 用例 A~E（手算对照、去极值逻辑、伙伴+随机、有/无伙伴对照、固定种子复现）
15. `README.md` — 功能说明、公式示意、快速开始、合规说明、已知限制、扩展清单

## 六、验证方式

1. **双击运行**：直接打开 `index.html`，载入示例方案，点"开始演算"，3 秒内出曲线与建议区间
2. **自检用例**：点击内置自检按钮，用例 A~E 全 pass（误差 ≤0.01 分）
3. **参数敏感性**：修改 K/a/b/家数/对手区间/伙伴均值，曲线与建议区间合理变化（对手越低→我方最优下移；伙伴越高→区间上移）
4. **种子复现**：同种子同参数两次运行逐位一致
5. **导入导出**：导出 JSON → 重新导入 → 复现同一方案
6. **合规检查**：合规提示条首页+报告页均显示，不可永久关闭；伙伴表在结果页完整回显
7. **性能基线**：k+m≤8、候选 30 档、模拟 10000 次，单次演算 ≤3 秒，UI 不卡死
